นโยบายความเป็นส่วนตัว

ข้อมูลสำหรับเจ้าของเครื่องและผู้ทดสอบที่ได้รับอนุญาต ใช้กับ UpVdo ในการทดสอบส่วนตัวและการเชื่อมต่อ TikTok Sandbox

ฉบับวันที่ 5 พฤศจิกายน 2026 · ขอบเขต: เครื่องมือในเครื่องและเว็บไซต์เอกสารนี้

ในหน้านี้ขอบเขตข้อมูลที่ใช้การส่งข้อมูลการเก็บรักษาการควบคุมและลบข้อมูลเว็บไซต์เอกสารการติดต่อ

1. ขอบเขตของเครื่องมือ

UpVdo เป็นโปรแกรมส่วนตัวที่รันบนคอมพิวเตอร์ของเจ้าของ โดยใช้ n8n ใน Docker ช่วยประมวลผลงาน ผู้ทดสอบเป็นผู้เลือกไฟล์และอนุญาตบัญชีปลายทาง ไม่มีระบบสมัครใช้บริการสาธารณะบนเว็บไซต์นี้

การทดสอบ TikTok อยู่ในขอบเขต Sandbox และบัญชีทดสอบที่อนุญาต เอกสารนี้ไม่ได้ระบุว่าแอปได้รับอนุมัติสำหรับ production

2. ข้อมูลที่ใช้ในการทำงาน

ข้อมูลวัตถุประสงค์
วิดีโอที่ผู้ใช้เลือก รวมภาพ เสียง และเนื้อหาที่ปรากฏวิเคราะห์เนื้อหาและดำเนินการเผยแพร่เมื่อผู้ใช้สั่ง
ชื่อไฟล์ ชนิดไฟล์ ตำแหน่งไฟล์ในเครื่อง และค่าแฮชของไฟล์อ่านไฟล์ สร้างชื่อวิดีโอจากชื่อไฟล์ และช่วยตรวจการอัปโหลดซ้ำ
คำอธิบาย แฮชแท็ก คำค้น และการตั้งค่าปลายทางเตรียมข้อความสำหรับโพสต์ รวมการเผยแพร่ เวลา และเพลย์ลิสต์ที่เลือก
ข้อมูลการอนุญาตบัญชีและการเชื่อมต่อ APIให้เครื่องมือดำเนินการกับบัญชีที่ได้รับอนุญาตตามสิทธิ์ที่ให้ไว้
รหัสงาน รหัสวิดีโอ ลิงก์ สถานะ ข้อผิดพลาด และเวลาทำงานแสดงผล ตรวจงาน และเก็บใบรับในเครื่อง

โทเคนและข้อมูลการเชื่อมต่ออยู่ตามการตั้งค่าของเครื่องและ n8n ไม่ได้รวมอยู่ในไฟล์เว็บไซต์เอกสารนี้

3. ข้อมูลถูกส่งไปที่ใด

  • Google Gemini: n8n ส่งวิดีโอที่เลือก รวมภาพและเสียง พร้อมบริบทชื่อไฟล์ เพื่อให้ AI สร้างคำอธิบาย แฮชแท็ก และคำค้น แม้เป็นโหมดสร้างตัวอย่าง ขั้นตอนนี้ยังส่งข้อมูลไปยัง Gemini
  • YouTube: เมื่อผู้ใช้เลือกและสั่งอัปโหลด จะส่งวิดีโอ ชื่อ คำอธิบาย แฮชแท็ก คำค้น และการตั้งค่าที่เกี่ยวข้องไปยังบัญชีที่อนุญาต
  • TikTok: เมื่อการเชื่อมต่อ Sandbox พร้อมและผู้ใช้อนุญาต จะส่งวิดีโอหรือข้อมูลที่จำเป็นต่อการอัปโหลด พร้อมคำบรรยายและการตั้งค่าที่ API และบัญชีทดสอบรองรับ
  • ระบบในเครื่อง: สำเนาพักงาน ไฟล์สถานะ ใบรับ และประวัติการรันอาจอยู่ใน Docker, n8n และโฟลเดอร์ของผู้ใช้

บริการภายนอกจัดการข้อมูลตามเงื่อนไขและนโยบายของตน รวมข้อกำหนดบัญชี API และการเก็บข้อมูล ผู้ใช้ควรตรวจนโยบายปัจจุบันจากเว็บไซต์ทางการของ Google, YouTube และ TikTok ก่อนเชื่อมบัญชีหรือส่งวิดีโอ

ไม่ควรเลือกไฟล์ที่มีข้อมูลของผู้อื่นหรือเนื้อหาที่ตนไม่มีสิทธิ์ส่งไปยังบริการเหล่านี้

4. การเก็บรักษาข้อมูล

UpVdo เก็บวิดีโอต้นฉบับไว้ในตำแหน่งที่ผู้ใช้เลือก สำเนาพักงานใน Docker ถูกล้างตามเส้นทางงานที่สำเร็จ ส่วนงานที่ล้มเหลวหรือสำเร็จบางส่วนอาจเก็บสำเนาไว้เพื่อให้ตรวจสอบต่อได้

ใบรับใน .upvdo-receipts และไฟล์ตัวอย่างคำอธิบายยังอยู่ในเครื่องจนกว่าผู้ใช้จะจัดการเอง ประวัติการรันและข้อมูลไบนารีของ n8n อาจยังคงอยู่ตามการตั้งค่า n8n แม้สำเนาพักงานถูกล้างแล้ว

วิดีโอหรือข้อมูลที่ส่งไปยังบริการภายนอกมีระยะเก็บรักษาตามบริการนั้น การลบไฟล์ในเครื่องไม่ได้ลบข้อมูลหรือโพสต์บนบริการภายนอกโดยอัตโนมัติ

5. การควบคุมและลบข้อมูล

  • หยุดงานก่อนเริ่มส่งข้อมูล และเลือกใช้โหมดตัวอย่างเมื่อต้องการตรวจคำอธิบายก่อนเผยแพร่ โดยโหมดตัวอย่างยังใช้ Gemini วิเคราะห์วิดีโอ
  • ตรวจและลบไฟล์ตัวอย่างหรือใบรับในโฟลเดอร์ของตนได้ การลบใบรับอาจทำให้เครื่องมือไม่มีหลักฐานเดิมสำหรับช่วยกันอัปโหลด YouTube ซ้ำ
  • จัดการสำเนาพักงาน ประวัติการรัน และข้อมูลไบนารีผ่านผู้ดูแลเครื่องหรือ n8n โดยตรวจให้แน่ใจก่อนว่าไม่มีงานกำลังใช้งานไฟล์นั้น
  • เพิกถอนสิทธิ์บัญชีในหน้าจัดการบัญชีของผู้ให้บริการ และนำข้อมูลเชื่อมต่อที่ไม่ใช้แล้วออกจาก n8n หรือการตั้งค่าในเครื่อง
  • แก้ไขหรือลบวิดีโอที่เผยแพร่ผ่านบัญชี YouTube หรือ TikTok ของตน การดำเนินการนี้ต้องทำแยกจากการลบใบรับในเครื่อง

6. เว็บไซต์เอกสารนี้

ไฟล์เว็บไซต์นี้เป็นหน้า HTML และ CSS ไม่มีแบบฟอร์มอัปโหลดวิดีโอ ไม่มีระบบเข้าสู่ระบบ ไม่มีคุกกี้หรือสคริปต์วิเคราะห์การเข้าชมที่ฝังไว้ในไฟล์หน้าเว็บ

หากนำหน้าเว็บไปโฮสต์ ผู้ให้บริการโฮสต์อาจบันทึกข้อมูลการเข้าถึง เช่น ที่อยู่ IP และคำขอหน้าเว็บ ตามการทำงานและนโยบายของผู้ให้บริการนั้น

7. การติดต่อ

ผู้ทดสอบติดต่อเจ้าของเครื่องหรือผู้ดูแล n8n ที่ให้สิทธิ์ใช้งานโดยตรง เพื่อสอบถามข้อมูล หยุดการเชื่อมต่อ หรือจัดการข้อมูลที่อยู่ในเครื่อง เครื่องมือนี้ไม่มีช่องทางบริการสาธารณะหรือระบบรับคำขอผ่านหน้าเว็บไซต์ และไม่ควรส่งรหัสผ่าน คีย์ API หรือโทเคนผ่านหน้าเว็บนี้

อ่าน เงื่อนไขการใช้งาน สำหรับขอบเขตการทดสอบและการตรวจผลลัพธ์ก่อนเผยแพร่ หรือกลับไป ข้อมูลเครื่องมือ
